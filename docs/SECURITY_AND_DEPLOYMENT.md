# Local security boundary and deployment requirements

Better Auth uses password authentication, persisted sessions, database-backed rate limits and disabled session cookie caching. Academy membership and player scope are checked separately from authentication. Mutation APIs require the configured public origin. Tenant queries include academyId; parent queries additionally join explicit guardian relationships. Coaches see assigned players, parents see their own linked players and approved snapshots, and platform administrators have no default academy membership. Responses and PDF exports use private no-store caching.

SQLite persistence uses Node's native SQLite API, WAL, foreign keys, transactions, approval history and audit records. The default file is `.local/workspaces.sqlite`; authentication uses a generated ignored local secret. Neither this file, local secrets, provider credentials nor real phone numbers belong in Git. Node 24 is recommended. `SPORTOZEN_DATABASE_PATH` may select a durable local disk. This single-host setup must not be deployed onto an ephemeral/serverless filesystem or shared concurrently across network disks.

For a deployed host, configure HTTPS `BETTER_AUTH_URL`, a strong server-side `BETTER_AUTH_SECRET`, durable database storage, backup/restore and operational monitoring. Review migrations and provision platform administrators explicitly. Replace local SQLite with a supported managed database before multi-instance deployment. Add verified account ownership, secure recovery, MFA for staff, invitation delivery, retention/deletion, guardian identity verification procedures, consent records, abuse controls, audit retention, media object permissions and independent security review before admitting real children’s records. No messaging, billing, AI or clinical nutrition service is connected.

The legacy `/owner`, `/coach` and `/parent` routes remain explicitly fictional browser demonstrations. Their role switcher is not authentication. Secure customers use `/workspace`; legacy browser storage is never trusted as server authorisation or imported automatically. Production routing must retire or isolate demo entry points and their seeded media. Authenticated dated sessions, attendance and coach-recorded evidence now use the workspace boundary; secure video upload, reports configuration, quiet-hour dispatch and fee operations remain separate work.

Training records are checked by academy, current membership, module, football assignment, session coach and player assignment. Parent/support cannot query raw training kinds or history. Reviewed eligible content reaches parents only through approved private snapshots; internal evidence/conversation notes are excluded. Request receipts, version guards, history and audit are committed atomically. Database fault and bulk conflict tests verify rollback. These safeguards apply to the new training commands and guarded workspace edit/review controls, not an untested blanket guarantee for every older API. Before real child-data deployment, complete the production prerequisites above; supervised synthetic-data pilot readiness is a narrower claim.

The request tests exercise actual cookies and APIs, forbidden cross-academy reads/writes/exports, linked-parent snapshots, hidden notes, approval reset and membership revocation. This validates tested routes, not all future integrations or a complete commercial security certification.

Browser tests start their own production server on port 3001 with a guarded `.local/e2e-*.sqlite` database. A controlled persistence check starts/restarts only its own process on port 3002. Do not stop the customer's app on port 3000 or reset `.local/workspaces.sqlite`. Use `SPORTOZEN_QA_BUILD=1` for both build and browser tests when preserving the running app's assets. Raw authentication traces remain ignored locally and are not uploaded by CI.

The release is football-only. Historical non-football records remain in restricted storage without relabelling or deletion; customer APIs/UI/PDFs exclude them. Regional settings and independent academy privacy remain unchanged. See FOOTBALL_ONLY_RELEASE.md.
