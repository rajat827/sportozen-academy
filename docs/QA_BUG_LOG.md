# Football release QA findings — 12 October 2026

All reproduction uses synthetic records and an isolated test database. Customer and legacy-demo results are separate. Severity reflects the football release requirement, not a claim that the previous multi-sport scope was unintended.

| ID | Severity / area | Reproduction, expected and prior behaviour | Fix / verification |
| --- | --- | --- | --- |
| FB-001 | P1 / scope enforcement | Owner onboarding/configuration offered other sports; valid API requests could create/enable them. Expected: football automatic, unsupported sports rejected. | Selectors removed; server schemas default to football and reject unsupported values for academy, player, plan, drill, report, update and programme. Unit and authenticated API tests cover cricket, badminton and an unknown sport. |
| FB-002 | P1 / historical access | Previously valid direct links returned non-football records and PDFs. Expected: preserve storage, restrict active release access. | Staff/parent/support projections exclude historical sports and linked records. Synthetic historical bodies remain identical after rejected reads/edits and a settings save. Direct record/PDF checks return 404; conversation PUT returns its existing 405 method prohibition. |
| FB-003 | P1 / failed save | Owner submits a player and the backend fails: player name was cleared despite no saved result. Expected: keep editable draft for retry. | Clear only after a successful save. Browser fault injection returns 503 once, verifies retained name, then retries against the real API. |
| FB-004 | P1 / coach privacy | Coach authorised only through a historical non-football child could receive that family's guardian name in membership metadata. Expected: football-authorised assignments only. | Guardian membership query requires the assigned player's football participation. Historical fixture explicitly assigns the old player to the coach and restores the guardian link; coach response excludes the guardian. |
| FB-005 | P2 / misleading configuration | Historical other-sport-only academy could be labelled as already configured for football. Expected: activation required, no relabelling. | Academy cards/header show Football configuration required until owner/admin saves football settings. No historical child/plan is converted. This edge's copy was code-reviewed; the automated historical fixture is a mixed academy. |
| QA-001 | P1 / test environment | Tests assumed port 3000 and a general env-selected database; running them required stopping the app. Expected: isolated server/DB. | Tests use 3001 and guarded e2e filenames; restart test owns port 3002 processes. QA build output is separate. Customer DB and running server are preserved. |
| QA-002 | P1 / shared artifacts | CI uploaded retained failure traces that can contain auth material. Expected: sanitised evidence only. | Raw traces stay ignored locally; CI uploads screenshots/PDF artifacts only. No cookies, invitation tokens or credentials are included in committed QA captures. |
| BLOCK-001 | P1 / sessions | Authenticated customer record kinds have no session or personalisation workflow. | NOT_IMPLEMENTED. Full football training pilot blocked; demo personalisation is not customer acceptance. |
| BLOCK-002 | P1 / attendance/evidence | Customer record kinds have no attendance ledger, structured training evidence or secured media workflow. | NOT_IMPLEMENTED. Report observations can be entered/reviewed, but are not a verified session/evidence pipeline. |
| PROD-001 | Production / persistence | Version counters exist, but optimistic edit conflict protection and retry idempotency are not established by this release. | Concurrency and interrupted-commit recovery are NOT_TESTED; secure production rollout must address them. | PDF-001 | P2 / existing long-PDF visuals | Render the three-page legacy long fixture: repeated academy header/private footer text is absent visually on pages 2/3 although extracted text contains it; body and page numbers are visible. Expected: visible repeated branding/privacy footer. | OPEN, pre-existing renderer unchanged by scope update. All pages reviewed; main authenticated one-page report passes visual/fact checks. Text-only automated checks do not cover this raster defect. |

Build verification initially caught an incorrect Playwright helper type; it was corrected using the request-factory type and gates rerun. The first historical-link test expected 404 for conversation PUT; that route deliberately disallows all direct conversation PUTs with 405. The assertion now checks that exact prohibition and still verifies unchanged historical storage. A failed-save test initially matched Next.js's route-announcer alert as well; the selector now targets the specific save-error alert without weakening its text/value checks. No success, privacy or preservation assertion was removed.
