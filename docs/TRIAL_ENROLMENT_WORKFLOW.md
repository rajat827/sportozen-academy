# Trial enrolment workflow

Trials extend the existing authenticated player, batch, training, guardian and finance records. They do not create a second player database. Trial fixtures are kept separate from the stable Bharat60-player reporting scenario.

Owner/Admin configure the academy policy: optional default duration in days, whether paid trials are allowed, approved fee amount/currency and the billing explanation. There is no fixed seven- or fourteen-day policy. A trial always has explicit start/end dates, the existing player’s current assigned batch and responsible active coach. The optional default duration helps fill the end date; the saved dated enrolment is authoritative. Invalid/reversed dates, mismatched assignments, unapproved paid rules and overlapping active/scheduled/completed trials are rejected.

The lifecycle is Scheduled → Active → Completed or Expired, with explicit Cancelled, Not Converted and Converted decisions where allowed. Expiry is projected using the academy timezone and inclusive end date; an ended Active/Scheduled trial is shown as Expired. Status changes require reasons and versions. Trial state is separate from profile archiving. Creating or converting an archived profile requires restoring that profile; ending a trial does not delete attendance, observations or relationships.

In Players, the selected player’s existing detail panel has a native Trial enrolment section and dialogs. Owner/Admin manage rules, enrolment, decisions, reviewed summaries and explicit invoices. The assigned coach may record trial feedback within the current player scope. Parent and cross-academy writes are rejected. Staff feedback remains private. Loading/failure states retain the draft; confirmed saves are distinguished from failed list refreshes.

Conversion requires explicit review and a reason, and updates the existing player to regular/active status. It preserves the player ID, guardian links, past sessions, attendance, coach observations, trial history and finance records. Repeated conversion does not create another person or a charge. Cancelled/Not Converted trials cannot be converted implicitly. Conversion itself never invoices current or historical sessions.

Free trials require a zero trial fee. Paid trial creation must match current approved academy rules, but creates no invoice or payment. An Owner/Admin deliberately issues one reviewed dated trial invoice through the existing finance service. Trial eligibility/version, invoice creation/reuse and trial linkage share one SQLite transaction. A failed linkage rolls back the financial record/history/request receipt; a retry can succeed without duplicate charges. Collection remains disconnected; manual payment references and actual verification use the existing finance workflow. Invoice creation does not establish a paid transaction.

Coach-reviewed trial summaries use actual completed roster sessions, attendance and reviewed parent-eligible observations within the dated trial period. Without reviewed observations, the summary must state insufficient reviewed evidence. Raw feedback does not publish automatically. Parent publication is a separate explicit command; only currently linked guardians see the published summary. Staff notes, raw sources, lifecycle history and invoice IDs are omitted from the parent trial projection. A source/attendance change withholds stale reviewed/public content without erasing stored history. A trial does not automatically produce a full monthly performance assessment.

Persistence: additive migration005 adds academy-scoped policies, enrolments and request receipts. Existing workspace and finance tables remain authoritative for people/training/transactions. Trial writes use current membership checks, expected versions, request digests, audit records and safe integer minor-unit money.
