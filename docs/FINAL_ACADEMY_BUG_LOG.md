## BUG-FEE-02 — invoice creation inherited another account's currency

Source review found that the shared fee editor selected `invoice?.currency` before `selectedPlan?.currency` even in new-invoice mode. Fees supplies its selected account to that editor, so an existing INR invoice remained the currency context when the owner chose a GBP plan for a new invoice. The resulting GBP-plan amount with INR currency is rejected by the existing server currency guard. This is an identified form-data defect; no claim is made that the old branch was browser-reproduced for this additional finding.

The minimal fix makes currency mode-specific: fee-plan editing uses its own chosen currency; new invoices use the chosen plan's currency or academy currency for an individual charge; reference/verification/adjustment flows keep their actual invoice currency. Server currency validation, issued records, amounts, academy context and approved UI are unchanged.

The independent second case in [fee-plan-save.spec.ts](../tests/e2e/fee-plan-save.spec.ts) uses a separate fictional academy: existing INR account selected → GBP fee plan → explicit new GBP invoice, exact plan minor units and unchanged INR invoice. The inverse check opens an individual academy-currency charge while the GBP account is selected. The independent currency browser case **passed in full run 64258 (59/59,16.4 minutes,exit 0)**. The [actual currency manifest](screenshots/final-academy/regression/final-fee-save/currency-context/invoice-currency-context.json) records an existing INR account followed by a GBP-plan invoice for exactly 120050 minor units, the existing INR invoice unchanged, and an inverse individual charge correctly showing INR while the GBP account is selected. There are **two explicitly issued invoices, zero automatic invoices and zero payments**. The original [QA-15 fixture](screenshots/final-academy/regression/final-fee-save/after/qa-15.json) separately retains zero invoices and zero payments, one Save POST and persistence after fresh login. Scoped lint and build 20818 passed.
