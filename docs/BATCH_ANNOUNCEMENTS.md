# Batch operational announcements and scheduled weekly drafts

This extends the authenticated Messages workflow. It reuses the existing academy sender, consent records, delivery_jobs queue, worker, transport adapter, signed provider events and audit history. It does not enable sending or create a second provider/queue.

Staff choose one, multiple or all currently authorised batches. Select All expands only the current authorised selection; approval freezes those batch IDs rather than silently adding future batches. Coaches cannot widen access beyond their assigned batches. Owner/Admin approval is mandatory. Parent and Support requests are rejected server-side.

The preview resolves current guardian links and active memberships, verifies existing contact evidence/academy consent, and checks the separately recorded operational category preference. Existing contacts do not acquire this preference automatically. E.164 contact identifiers are normalised and deduplicated across children and selected batches. The preview shows actual eligible counts, duplicate removal, masked contact endings, exclusions and provider blockers. No child names or development details are interpolated; known child identities and contact details are rejected in generic bodies, and the reviewer must confirm generic privacy. Personal content belongs in a private child conversation.

Draft → pending approval → approved snapshot → explicitly queued are separate commands. Version checks, UUID/digest request receipts and immutable announcement history protect repeated submissions. Approval freezes final rendered content and recipient/contact fingerprints. Queue and dispatch recheck current authority, guardian links, consent, preferences, template name, expiry and source version. Changing a selected batch or contact requires a fresh review. Generic announcements have no selected child ID; replies without a valid child context remain ambiguous for authorised staff clarification.

Urgency is a label, and does not bypass consent, approval, quiet hours, exact provider templates, test-recipient restrictions or server sending flags. The proposed local operational template is `sportozen_operational_announcement`, body `{{1}}: {{2}}. {{3}} Reply STOP to opt out.` in `en_GB`. This is a local definition, **not** a Meta-approved template. Its actual approved provider name must be saved by the academy; provider verification checks exact text/language/status again. Configuring it also requires re-verifying the sender. No credentials, template submission or provider activation are performed here.

Weekly automatic draft preparation is separately disabled by default. Academy Settings can specify preparation lead days/time before the notification schedule. The existing supervised worker creates only missing child/week drafts through the existing period service. It never overwrites saved human drafts, approves them or publishes them. Batch plans remain the default; a missing individual plan does not block preparation. Snapshots include recorded sessions, timezone-correct dates/times, venue, shared focus, activities and preparation instructions. Existing approval/private-publication rules remain required. Session cancellation/rescheduling invalidates affected unissued approvals and queued weekly content; dispatch rechecks source versions. Template budgets reject overlong content rather than silently removing sessions.

Provider requirements were checked against [WhatsApp Business Messaging Policy](https://whatsappbusiness.com/policy/) and [Meta's approved template guidance](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/api-reference/messages/template/). The application deliberately retains its stricter recorded academy consent/category safeguards. Template approval, connected WABA/phone, academy-bound secrets, verified recipient consent, supervised worker, webhook delivery, and sending flags remain external prerequisites. Automated verification uses synthetic records and test transports only.
